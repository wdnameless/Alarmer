# Аудит: Alarmer как универсальный будильник

Вопрос: годится ли приложение на роль **обычного будильника** — того, который
человек ставит на 7:00 и больше о нём не думает. Проверка по шагам самого
частого сценария, а не по ощущениям.

## Что уже работает

| Сценарий | Состояние |
|---|---|
| Звонит при скрытом окне, в трее, без окна | Да — планировщик в Rust, звонот через системное аудио |
| Звонит на любом экране приложения | Да — `AlarmCenter` над вкладками |
| Не повторяет звонок после «Остановить» | Да |
| Snooze 5/10/15 | Да |
| Пропущенный звонок виден | Да — баннер «Пропущено сегодня» |
| Переживает перезапуск/сон | Да, с окном догона 5 минут |
| Автозапуск с системой | Да, свёрнутым в трей |
| Один раз / каждый день / по дням | Да |
| Нарастание громкости, повтор до подтверждения | Да |

Основа надёжная: это уже не «игрушечный будильник, который молчит, если
свернуть окно».

## Что мешало (исправлено в этом проходе)

| # | Проблема | Почему это важно для будильника |
|---|---|---|
| 1 | **Нельзя выбрать дни недели.** Пресет «По дням» жёстко означал Пн–Пт | Будильник «только по субботам» был невыразим |
| 2 | **Нельзя изменить будильник.** Ни время, ни дни — только удалить и создать заново | Опечатка в 07:30 вместо 07:00 стоила двух действий |
| 3 | **Нет описания к будильнику** | Просыпаясь, человек не помнит, зачем звенело |

Все три закрыты: чипы дней недели при создании и на самом будильнике,
время правится на месте, описание пишется и показывается на экране звонка.

## Что осталось (по убыванию влияния)

| # | Проблема | Оценка |
|---|---|---|
| 4 | **Окно 260×420, минимум 220×360.** Текст в основном 10–11px. Для будильника это тесно: список из 5 будильников требует прокрутки, а кнопки попадают под палец с трудом | Средняя: работает, но ощущается как виджет, а не приложение |
| 5 | **Нет повторов звука на пользовательский файл через UI.** Поле `alarmer_custom_alarm_sound` читается, но записать его неоткуда | Низкая: встроенные профили покрывают обычный случай |
| 6 | **Будильник нельзя привязать к дате.** Только «один раз» и «дни недели» — нет «1 сентября» | Низкая для будильника, средняя для напоминания |
| 7 | **Нет проверки «сработает ли».** Не видно, сколько времени до следующего звонка, кроме экрана «Сегодня» | Низкая |
| 8 | **Нет таймера сна / засыпания** | Низкая: нишевая функция |

## Вывод

Как **универсальный будильник** приложение теперь состоятельно: надёжность
звонка, догон пропущенного, произвольные дни и правка на месте — это ровно
то, чего ждут от будильника. Остаточные пункты 4–8 — это уже «приятно иметь»,
а не «не работает».

Главное ограничение — **размер окна** (пункт 4): приложение задумано как
компактный таймер, и на роли «будильник на весь экран» это сказывается.
Расширять окно стоит только вместе с переработкой компоновки, иначе
получится пустое пространство вокруг тех же 340px колонки.
