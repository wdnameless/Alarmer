# Proposal: Schedule-First Product

## Why
Аудит подтвердил структурную причину ощущения «не премиум»:

```
src/types/index.ts  AlarmItem { time, days, label }   — одиночный момент
grep "schedule"     → сущности нет (только флаг showAiScheduleButton)
```

Пользователь не может сохранить расписание, включить его целиком, отредактировать
как единицу или переиспользовать ежедневно — потому что сохранять нечего.
ИИ создаёт N разрозненных записей в плоском списке, и на этом связь заканчивается.

Дополнительно: `WorkoutRoutine` объявлен в типах, но плеер был удалён при чистке
мёртвого кода (тогда он был недостижим — решение было верным). Задача пользователя
требует вернуть интервалы, теперь по-настоящему подключёнными к расписанию.

## Модель
- **Schedule** — главная сущность: имя, исходный текст, шаги, дни, включённость.
- **ScheduleStep** — либо момент времени (звонит будильник), либо интервальный блок
  (последовательность упражнений с таймером и голосом).
- Развёртывание: включённые расписания проецируются в срабатывания, которые
  планировщик уже умеет обрабатывать. Существующий `AlarmItem` остаётся
  примитивом уровня планировщика, а не пользовательским объектом.
