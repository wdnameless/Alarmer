# Proposal: Reliability and Product Depth

## Why — аудит нашёл дефекты, которые гейты не ловят

`bun run check` (tsc + eslint + vitest, 59 тестов) и `cargo test` (8 тестов)
проходят зелёными, но flagship-функция в состоянии по умолчанию не работает.
Причина структурная: **весь UI не покрыт тестами** (`vitest.config.ts` →
`environment: 'node'`, компонентных тестов нет), а оба P0-дефекта живут
в жизненном цикле React-компонентов.

### P0-1. Будильник не звонит на вкладке по умолчанию

`grep` подтвердил: слушатель `alarm://fired` объявлен в `Alarms.tsx:85`,
а `Alarms` монтируется только при `subModule === 'alarms'`
(`DashboardView.tsx:101`). Дефолтный модуль — `'today'` (`App.tsx:37`).

Rust (`scheduler.rs:245`) испускает событие всегда, но нативное уведомление
и показ окна делает только `if !visible`. Окно открыто и видимо → события
никто не слушает, уведомления нет, звука нет. `invoke('sync_alarms')`
там же (`Alarms.tsx:66`) — если вкладку не открывали, планировщик пуст.

### P0-2. Кнопка «Остановить» не останавливает будильник

`scheduler.rs:81` в `dismiss()` снимает `fired`-маркер. Цикл опрашивает
раз в 500 мс и матчит `a.time == hhmm`. После подтверждения маркер снят →
тот же будильник звонит снова через полсекунды, до конца минуты.
Подтверждено падающим тестом (написан, прогнан, удалён):
`left: 1, right: 0`.

### P0-3. Таймер не переживает переключение под-вкладки

`Timer` смонтирован условно (`DashboardView.tsx:100`). Состояние отсчёта
живёт только в компоненте: уход на «Алармы» → обнуление. Следствия:
`MiniOverlay` замирает (`timer://tick` эмитит только смонтированный `Timer`),
глобальные хоткеи молча ничего не делают, финиш при скрытом окне — тишина.

## Model
- **Владелец времени — Rust.** Часы таймера переезжают в backend по образцу
  планировщика: фронтенд становится представлением состояния, а не его
  хранилищем. Один источник истины для UI, оверлея и хоткеев.
- **Срабатывания принадлежат приложению, не вкладке.** `sync_alarms` и
  `listen('alarm://fired')` поднимаются на уровень `App`; takeover звонка
  рендерится вне под-вкладок.
- **Семантика `days: []` — одна.** Сейчас три источника противоречат друг
  другу (`types/index.ts:84` «once», `ai.ts:72` «один раз», `scheduler.rs:196`
  «каждый день»). Приводится к явной модели повтора.
- **Задача — новая сущность.** Расписание отвечает «когда», но не «что
  именно». Задачи связываются с шагами и дают статистику — единственный
  удерживающий контур в категории time-management.

## Порядок работ
1. Сеть безопасности: jsdom + testing-library + CI (иначе следующий дефект
   такого класса снова уедет)
2. Надёжность будильников: dismiss, уровень приложения, семантика дней, catch-up
3. Надёжность таймера: часы в Rust, финиш при скрытом окне
4. Звук в Rust: профили, пользовательский файл, TTS при скрытом окне
5. Ужесточение ИИ: любой baseUrl, ключ в keyring, честные ошибки
6. Продукт: задачи + история сессий + статистика
7. UI: темы, i18n, доступность
8. Гигиена: мёртвый код, метаданные
