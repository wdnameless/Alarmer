# Proposal: Focus Budget Program

## Why

Пользователь указал эталон: `focuslimit.io`. Их модель отличается от нашей не
набором экранов, а единицей учёта.

У нас единица — **сессия**: сколько времени прошло. У них — **блок** внутри
**направления** с недельным бюджетом, и главный сигнал — **качество фокуса 1–10**,
которое пользователь ставит после каждого блока. Их формулировка: «Фокус — это твои
20%, и такого времени у тебя около 25 часов в неделю»; «Потратил бюджет —
переключайся»; «Качество фокуса — главный сигнал».

Проверено по коду: понятий `budget`, `направление`, `quality` в проекте нет.
`grep -riE "budget|direction|weekly|quality|rating"` по `src/` не даёт ни одного
продакшн-совпадения. `TimerMode = 'countdown' | 'flow'` — фазы отдыха нет,
счётчика блоков нет, оценки нет.

Отсюда следует не «добавить страницу статистики», а ввести единицу учёта, к которой
привязываются бюджет, цикл и оценка. Существующие сессии при этом сохраняются.

## Что меняется

- **Direction** — новая сущность: имя, цвет, недельный бюджет в блоках, архив.
- **Блок** — фокус-фаза + автоматическая фаза отдыха (50/10, настраивается, пресет 25/5),
  счётчик блоков за день. Отдых не пропускается одним нажатием: смысл в том, чтобы
  перерыв действительно случался.
- **Качество 1–10** — спрашивается после каждой фокус-фазы в режиме блока, можно
  пропустить; хранится в записи сессии.
- **Журнал** — вкладка «Итоги» становится «Журналом»: уровень «Неделя» (каждая
  неделя против своего лимита), уровень «Месяц» (строка — неделя, квадрат — блок),
  светофор по направлениям и общий. Неделя начинается с понедельника.
- **Музыка** — одна ссылка, играет в фокусе и замолкает на отдыхе.
- **ИИ** — отвечает по агрегированной истории журнала и умеет создавать направления
  и бюджеты, как уже умеет создавать будильники.

## Модель данных (хранилище v5 → v6)

```ts
interface Direction {
  id: string;
  name: string;
  color: string;
  weeklyBlockBudget: number;   // блоков в неделю
  archived: boolean;
}

interface SessionRecord {
  // …существующие поля без изменений…
  directionId?: string;        // нет — значит «Без направления»
  quality?: number;            // 1..10, только для блоков
  blocks?: number;             // дробное: 25 мин = 0.5 блока
}
```

Сессии без направления продолжают считаться в общий фокус и часы, но не в бюджеты —
иначе выдуманная история в бюджетах. Поле `blocks` может отсутствовать у старых
записей: оно вычисляется из `focusedSec`, когда не сохранено.

## Не входит в объём

Аккаунты, облачная синхронизация, платежи, MCP-коннектор, синхронизация с Obsidian,
встроенные музыкальные треки. Причины: у нас локальное офлайн-приложение без бэкенда
и без аккаунтов, а встроенная музыка — лицензионные обязательства в публичном
репозитории. Решение пользователя (вопросы 10, 9, 8).

## Влияние

Миграция v6 добавляет поля, ничего не удаляя; старые сессии и экспортированные
бэкапы загружаются без потерь. Режимы `countdown` и `flow` работают как прежде.
Покрытие пороговое (53/50/50/54) — новые сервисы тестируются.

## Порядок работ

1. Модель, хранилище v6, миграция.
2. Сервис бюджета и журнала (расчёт, без UI).
3. Цикл блока в таймере (Rust) и вкладка Сегодня как точка старта.
4. Оценка качества.
5. Музыка с фокус/отдых-переключателем.
6. Журнал: неделя, месяц, светофор.
7. ИИ по агрегированной истории.
8. Проверка и приёмка.
